## Base URL

Use the API URL configured for your RelayRTC deployment, with the `/v1` prefix. Local development uses `http://localhost:8080/v1`.

The examples use `RELAYRTC_API_URL` for that base and `RELAYRTC_SECRET_KEY` for your secret key.

```bash
curl "$RELAYRTC_API_URL/" \
  -H "Authorization: Bearer $RELAYRTC_SECRET_KEY"
```

## Authentication

Pass a bearer API key on every request. Management endpoints require a secret key and the documented scope.

See [authentication](/reference/api/v1/authentication) for scopes and environment boundaries.

## Request and response bodies

Use `Content-Type: application/json` for JSON writes. Successful objects are returned directly, without a `data` wrapper.

Room and participant lists return `nodes` and `pageInfo`. Streaming collections generally return `data` and `nextCursor`; webhook lists use offset pagination. Some bounded streaming lists have no pagination. See [pagination formats](/reference/api/v1/pagination) for each family. A `204` response has no JSON body.

Unknown fields are rejected by strict request schemas.

Example IDs, dates and credentials are illustrative. Use resource IDs and secrets returned by your deployment.

## Transport

This reference documents HTTP endpoints. Joining a live room, sending in-room messages and transferring audio/video use the browser SDK and signaling service.

## Version and request headers

Responses include `x-relayrtc-api-version: v1` and `x-request-id`. Include the request ID when investigating an error.

[Streams REST](/reference/api/v1/streams) documents stream configuration, source sessions, grants, usage and durable operations when streaming is enabled.
