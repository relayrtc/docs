## Availability
Unreleased Phase 1 additions to the local @relayrtc/node build require the matching Phase 1 API and migration. Keep RelayServer and its secret key on the backend.

```ts
const run = await relay.broadcasts.create({
  streamId, name: 'Demo run', outputs: [{ kind: 'hls' }],
})
const start = await relay.broadcasts.start(run.id, { version: run.version }, {
  idempotencyKey: applicationCommandId,
})
const operation = await relay.streamingOperations.get(start.id)
const detail = await relay.broadcasts.get(run.id)
const outputs = await relay.broadcasts.getOutputs(run.id)
const page = await relay.broadcasts.list({ streamId, state: 'live', limit: 30 })
const stop = await relay.broadcasts.stop(run.id)
```

| Method | Result |
| --- | --- |
| broadcasts.create(input, options?) | BroadcastResource |
| broadcasts.list(query?, options?) | BroadcastPage: data, nextCursor, environment limits |
| broadcasts.get(id, options?) | BroadcastDetail with usage |
| broadcasts.start(id, input?, options?) | StreamingOperation |
| broadcasts.stop(id, input?, options?) | StreamingOperation |
| broadcasts.getOutputs(id, options?) | data: BroadcastOutput array |
| streamingOperations.get(id, options?) | StreamingOperation |

Input types CreateBroadcastInput, BroadcastCommandInput and ListBroadcastsQuery and all resource/output/status types are exported. Optional start/stop input contains version. Supply an empty input before request options when needed. Standard signal/timeout/retry options apply; mutations remain explicit one-attempt requests. Commands generate a UUID idempotency key unless supplied. Retry a lost response with the same application command ID, not a fresh key.

Create/start/stop require streams:write; reads require streams:read. Configuration is captured per run. Starting does not publish media; configure and start the source separately. A 202 operation is not live confirmation. Stop releases jobs without stopping the source. A terminal run cannot restart. Poll status or expose application-authorized callbacks to [useBroadcast](/reference/sdk/client/react/use-broadcast).

See [broadcast REST](/reference/api/v1/broadcasts) for exact fields, states, errors, limits and event contracts. Existing streaming operation kinds now also include broadcast.start/broadcast.stop; consumers using exhaustive switches should handle them.
