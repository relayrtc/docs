```ts
const windows = await relay.streams.clips.getWindow(streamId)
const source = windows.data[0]
if (!source) throw new Error('No retained media')
const clip = await relay.streams.clips.create(streamId, {
  recordingId: source.recordingId,
  interval: { kind: 'media', startSeconds: source.startSeconds, endSeconds: source.startSeconds + 10 },
  cutMode: 'precise',
}, { idempotencyKey: requestId })
const observed = await relay.clips.get(clip.id)
if (observed.state === 'ready') {
  await relay.clips.publish(observed.id)
  const grant = await relay.assets.createAccessGrant(observed.assetId, { action: 'playback' })
  // Return the grant only after your application authorizes its viewer.
}
```

streams.clips.create/list/getWindow/getBufferPolicy/setBufferPolicy and clips.get/publish/delete accept normal RequestOptions. create/list require a stream ID; list accepts cursor and limit. create accepts CreateClipInput with an explicit recordingId and typed ClipInterval. Commands automatically generate idempotency keys; supply a stable application request key when retries can cross backend requests. setBufferPolicy takes policy and the current version. Publish returns the observed ClipResource synchronously; deletion and creation return durable resources whose state must be polled.

For operator preview before publication, use `assets.createAccessGrant(assetId, { audience: 'preview', action: 'playback' })` with recordings:create authority. Viewers receive the default viewer audience only after publication. Existing recordings.getPlayback(clip.recordingId), assets.get and assets.createAccessGrant handle the resulting asset. A download grant uses action: download. Keep all management calls and API keys on your backend. See [REST errors and state](/reference/api/v1/clips) and [clip operations](/guides/clips-and-replay).
