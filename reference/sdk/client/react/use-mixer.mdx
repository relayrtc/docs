---
title: "useMixer"
description: "Follow desired and confirmed program versions through application-authorized studio endpoints."
section: "React SDK"
---

```tsx
const studio = useMixer({
  getMixer: signal => app.getMixer({ signal }),
  getOperation: (id, signal) => app.getMixerOperation(id, { signal }),
  activateScene: context => app.activateSavedScene(context),
  stop: context => app.stopMixer(context),
})
return <>
  <button disabled={!!studio.pending || studio.operation?.status === 'pending'}
    onClick={() => { void studio.activateScene() }}>Activate saved scene</button>
  <p>Requested {studio.mixer?.desiredVersion}; applied {studio.mixer?.appliedVersion}</p>
</>
```

Callbacks authorize studio operators on your backend; management keys and media-process options never enter the browser. Keep callback identities stable and bind an immutable saved scene/version payload for each command attempt. Command callbacks receive signal and idempotencyKey and return MixerCommandResult. getMixer returns MixerResource or null. Optional getOperation follows the pending operation ID and returns MixerOperation. Callback timeout/cancellation does not cancel an already committed server command; retry the same identity and reconcile status.

The hook returns mixer, operation, pending, error, isLive, isApplied, activateScene, stop and refresh. isApplied means a positive desired program revision matches its confirmed applied revision. Live/degraded state is observed separately; a source-loss slate can still have an applied scene. Polling stops on unmount and revisions prevent stale polls overwriting newer command responses. The browser package exports MixerClient with the same behavior.

Source and layout selection edit a local draft. Your backend saves it through mixers.putScene; activation references that saved version. Render draft controls separately from a BroadcastPlayer using the original stream's application-authorized playback metadata/grant. That player displays the server program, not a browser-composed arrangement. The existing streaming-foundation MixerPanel includes source/layout controls, host-only scene/operation endpoints and a program player. See [cloud video mixer](/guides/cloud-video-mixer) for setup and continuity limits.
