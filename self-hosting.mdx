This guide installs the complete RelayRTC stack using Docker: the console, API, calls, streaming workers, ingest gateway and private media storage. You will get a console at [localhost:3002](http://localhost:3002) and an API key for your application.

Start here for local testing. To make the installation accessible to other devices, follow [public hosting](/guides/self-hosting-operations#public-hosting-and-ports) afterward.

<Callout title="v0.1.2 release">
These instructions target v0.1.2. Its tag and container images must be published before downloading and starting this version. A missing download or image means the release is unavailable; use matching files and images from the same release.
</Callout>

## 1. Install and open Docker

Install [Docker Desktop](https://docs.docker.com/get-started/get-docker/) on Windows or macOS. Open it and wait for Docker to finish starting. On Windows, use Linux containers. Linux users can use Docker Engine with the Compose plugin.

The supplied release images target Linux AMD64. Check the release's supported architectures before using an ARM computer, including Apple Silicon. You do not need to install Node.js, Go or pnpm for this guide.

## 2. Download RelayRTC

1. Download the [v0.1.2 ZIP](https://github.com/relayrtc/relayrtc/archive/refs/tags/v0.1.2.zip) in your browser.
2. Extract the ZIP.
3. Open the extracted folder containing `docker-compose.yml`. Your ZIP program may put it inside another folder with the same name.

You should see these files, along with the rest of the release:

```text
relayrtc-0.1.2/
  .env.example
  docker-compose.yml
  docker-compose.streaming.yml
  docker-compose.release.yml
  docker-compose.streaming.release.yml
  infrastructure/
  scripts/
    configure-env.mjs
    prepare-streaming.mjs
```

Keep this folder for future starts and updates. Docker will download prebuilt services; you do not need to build the downloaded source.

## 3. Open a terminal in that folder

A terminal is the window where you paste the commands below. Run commands one at a time and wait for each to finish.

**Windows:** in File Explorer, open the folder from step 2. Click the address bar, type `powershell`, and press Enter. Use that PowerShell window throughout this guide.

**macOS or Linux:** open Terminal, type `cd ` with a space after it, drag the extracted folder into the terminal, and press Enter.

Check that Docker Compose is installed:

```sh
docker compose version
```

You should see a version number. If Docker is not found, finish its installation before continuing.

## 4. Create your settings file

Copy the command for your operating system. It creates `.env`, fills in the internal and streaming credentials, and prepares private monitoring files in `.streaming`. Streaming is included automatically.

### Windows PowerShell

```powershell
docker run --rm --mount "type=bind,source=$PWD,target=/workspace" --workdir /workspace node:24-alpine node scripts/configure-env.mjs
```

### macOS or Linux

```bash
docker run --rm --user "$(id -u):$(id -g)" --mount "type=bind,source=$PWD,target=/workspace" --workdir /workspace node:24-alpine node scripts/configure-env.mjs
```

Docker may download the Node.js image first. When finished, you should see `Prepared .env; prepared .streaming. No services were started.` Repeating this command keeps your existing configured keys. Keep `.env` and `.streaming` private; on Windows, restrict their file permissions to your account and Docker.

## 5. Fill in your sign-in and email settings

Open `.env` in a text editor. On Windows, use the same PowerShell window:

```powershell
notepad .env
```

On macOS or Linux, open the file in your editor. Files beginning with a dot may be hidden in your file manager.

Fill in these six settings. The [sign-in and email setup](/guides/self-hosting-authentication) explains where to get each value and gives the exact callback URLs.

| Setting in `.env` | Value to enter |
| --- | --- |
| `GITHUB_CLIENT_ID` | Your GitHub OAuth app's client ID |
| `GITHUB_CLIENT_SECRET` | Your GitHub OAuth app's client secret |
| `GOOGLE_CLIENT_ID` | Your Google web application's client ID |
| `GOOGLE_CLIENT_SECRET` | Your Google web application's client secret |
| `RESEND_API_KEY` | Your Resend email-sending API key |
| `RESEND_FROM_EMAIL` | A sender on your verified domain, such as `"RelayRTC <noreply@your-domain.com>"` |

Put each value after its `=` sign. The current account service requires both OAuth providers and email configuration, even when you plan to sign in with email and password. Complete [provider setup](/guides/self-hosting-authentication) before continuing.

Save the file as `.env`, keeping its exact name. Windows editors must not add `.txt`. For local testing, keep the generated keys, localhost addresses and other settings as supplied. Keep this file private and retain it across restarts.

## 6. Start RelayRTC

Run each command separately in the same terminal. These commands work in both PowerShell and Bash.

**Check configuration:**

```sh
docker compose --env-file .env -f docker-compose.yml -f docker-compose.streaming.yml -f docker-compose.release.yml -f docker-compose.streaming.release.yml config --quiet
```

Success produces no output. If a message names a missing setting, fill it in `.env` before continuing.

**Download the release images:**

```sh
docker compose --env-file .env -f docker-compose.yml -f docker-compose.streaming.yml -f docker-compose.release.yml -f docker-compose.streaming.release.yml pull
```

Wait for all downloads to finish. If an image is missing or access is denied, check that the release images are published.

**Start the services:**

```sh
docker compose --env-file .env -f docker-compose.yml -f docker-compose.streaming.yml -f docker-compose.release.yml -f docker-compose.streaming.release.yml up -d --no-build --wait
```

This prepares the database and private storage, then starts calls and streaming in the background. The first run can take several minutes. Keep all four Compose files in these commands: the first two define the complete services, and the last two select the prebuilt release images.

**Check the result:**

```sh
docker compose --env-file .env -f docker-compose.yml -f docker-compose.streaming.yml -f docker-compose.release.yml -f docker-compose.streaming.release.yml ps -a
```

Long-running services should be running, with healthy results where health checks are configured. Both `migrate` and `streaming-storage-init` are one-time setup services; `Exited (0)` is their successful result. The complete stack contains 16 services, including these two setup services.

## 7. Open the console and create an API key

1. Open [http://localhost:3002](http://localhost:3002).
2. Create your account and follow the verification email.
3. Create your organization and project. The project creates Development and Production environments for you.
4. Open the project's **Developer Controls**, then **API keys**.
5. Select **Development**, create a **Secret** key, and select `rooms:create` and `tokens:create` for the first-call example.
6. Copy the secret when shown and store it in your application backend's environment.

Use these connection addresses in the [first-call guide](/quickstart):

| Application setting | Local value |
| --- | --- |
| API base URL | `http://localhost:8080/v1` |
| Signaling URL | `ws://localhost:8081/v1/connect` |

Keep the secret key on your backend. Each caller receives their own participant token. Your frontend's origin must also appear in `RELAYRTC_SIGNALING_ALLOWED_ORIGINS`; the starter allows ports 3002 and 3005.

## Stop and troubleshoot

You can close the terminal after startup. Docker keeps the services running. End active calls, broadcasts and recordings before stopping the stack. Reopen a terminal in the installation folder and run:

```sh
docker compose --env-file .env -f docker-compose.yml -f docker-compose.streaming.yml -f docker-compose.release.yml -f docker-compose.streaming.release.yml down
```

This keeps your saved database and settings. To start again, use the `up` command from step 6.

If the console does not open, inspect the service logs:

```sh
docker compose --env-file .env -f docker-compose.yml -f docker-compose.streaming.yml -f docker-compose.release.yml -f docker-compose.streaming.release.yml logs --tail=100 api console migrate
```

| Problem | What to do |
| --- | --- |
| Docker cannot connect | Open Docker Desktop and wait for it to start |
| Compose file or `.env` not found | Reopen the terminal in the folder containing `docker-compose.yml`; check that the settings file is not named `.env.txt` |
| A required setting is missing | Complete the six provider settings in step 5 and save `.env` |
| Image download fails | Confirm the matching release images are published |
| Email is not arriving | Check the Resend sender and API key using [email setup](/guides/self-hosting-authentication#resend-email) |
| Sign-in returns a callback error | Use the exact URLs in [sign-in setup](/guides/self-hosting-authentication) |
| A port is already in use | Close the other application, or review [port settings](/guides/self-hosting-operations#local-endpoints) before changing `.env` |

For camera, microphone or remote-media problems, use [call troubleshooting](/guides/troubleshooting). Streaming is already running; use [streaming configuration](/guides/streaming-self-hosting) to check its addresses and test ingest/playback. For a deployment serving users, follow the [draining procedure](/guides/streaming-operations#upgrades-and-draining) before shutdown.
