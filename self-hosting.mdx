The RelayRTC `0.1.3` setup image generates configuration and starts the complete stack. Rooms, streaming, recording workers, private storage, TURN and monitoring are included. There is no separate streaming installation.

## 1. Start Docker

Install and open Docker Desktop on Windows or macOS, using Linux containers. On Linux, start Docker Engine. The installer bundles its own Docker CLI and Compose plugin. You do not need Node.js, pnpm, npm, Bun, Go, Git or a source ZIP.

Use Docker Engine 26 or newer (API 1.45+) for named-volume subdirectory mounts, with a Linux AMD64 or ARM64 engine. Windows containers are not supported.

## 2. Run setup

Run this single command in macOS Terminal, a Linux terminal or Windows PowerShell with Docker Desktop:

```sh
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock -v relayrtc-config:/setup/state ghcr.io/relayrtc/setup:0.1.3
```

The Docker socket gives setup access to create the application containers on this Docker engine. The named volume keeps configuration and secrets after the temporary installer exits. No host folder is required. Use the same trusted release for the installer and services.

Setup automatically:

1. Detects Docker and acquires an installation lock.
2. Generates missing credentials and saves them in `relayrtc-config`.
3. Downloads matching published images.
4. Starts PostgreSQL, private storage, database migration and all application services.
5. Waits for configured health checks and prints the console address.

Progress appears in the terminal. There is no installation wizard or temporary port `9095`. If setup stops early, its exit code is nonzero. Inspect the message before continuing. Configuration and data are retained.

For rootless Docker or a different socket location, replace the source side of the socket mount with your actual Docker socket. Docker Desktop must expose its Linux engine socket. Git Bash/MSYS users may need to disable automatic path conversion or use PowerShell instead.

## 3. Open the console

Visit [http://localhost:3002](http://localhost:3002), create your account through the normal signup screen, then create an organization and project.

For a fresh localhost installation, email/password signup works without GitHub, Google or Resend credentials. Email verification is automatically skipped only when no email sender is configured for this local installation. Password-reset emails, email changes and invitations need email delivery. Unavailable operations return an explicit configuration error. OAuth buttons appear only for configured providers.

Create an environment-scoped secret API key in **Developer Controls > API keys**. Keep it in your application's backend. For the [first call](/quickstart), grant `rooms:create` and `tokens:create`, then use:

| Setting | Local value |
| --- | --- |
| API base | `http://localhost:8080/v1` |
| Signaling | `ws://localhost:8081/v1/connect` |
| RTMP ingest | `rtmp://localhost:1935` |

Streaming is already included. Continue with [publishing a stream](/guides/streaming-ingest) or [broadcasts](/guides/broadcasts).

## Find your services

Docker Desktop groups the 16 services under the `relayrtc` Compose project. The setup container disappears after successful installation. The application containers continue running. `migrate` and `streaming-storage-init` are one-time services, so `Exited (0)` is expected.

Application services use restart policies. Start Docker after a host reboot. Existing services then restart according to those policies. The installer itself does not need to remain running.

## Start, inspect or stop

Run the same command again to resume installation or reapply saved settings at the same version. Existing configured credentials are preserved. An installation from a different version requires the explicit upgrade procedure.

Inspect status:

```sh
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock -v relayrtc-config:/setup/state ghcr.io/relayrtc/setup:0.1.3 status
```

Show recent service logs:

```sh
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock -v relayrtc-config:/setup/state ghcr.io/relayrtc/setup:0.1.3 logs
```

After ending active calls and draining broadcasts/recordings, stop application services:

```sh
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock -v relayrtc-config:/setup/state ghcr.io/relayrtc/setup:0.1.3 stop
```

`stop` retains PostgreSQL, storage, TURN and monitoring so it does not remove supporting services during cleanup. It deletes no volumes. Start saved services again with the same command ending in `start`, or start the project through Docker Desktop.

## Settings, public hosting and upgrades

The initial defaults are for browsers on this computer. Public hosting needs reachable addresses, HTTPS, configured email and media/TURN ports. See [operate RelayRTC](/guides/self-hosting-operations) for settings, importing an existing installation, backups and upgrades. [Optional sign-in and email settings](/guides/self-hosting-authentication) explains provider configuration.

The setup image's `help` command lists supported operations:

```sh
docker run --rm ghcr.io/relayrtc/setup:0.1.3 help
```

Source developers can keep using `pnpm env:configure` and `pnpm docker:up` from the repository. That development path builds source. The setup image installs published images.
