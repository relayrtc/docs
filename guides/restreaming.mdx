## Deploy the source worker
Apply migration 0037 and upgrade the API and workers together. Before running your normal streaming deployment command, configure:

```dotenv
STREAMING_SOURCE_ALLOWED_HOSTS=media.example.com,segments.example.com
STREAMING_MAX_SOURCE_JOBS=4
```

Replace these with exact public hostnames you control or are authorized to use. No wildcard or suffix matching is performed. Every redirect, nested playlist, initialization fragment and segment must use an allowed host, port 80 or 443, and resolve exclusively to public addresses. Your RelayRTC public API/RTMP hostname is excluded to prevent a playback-to-ingest loop. Private, loopback, link-local, metadata and non-global IPv6 addresses are blocked. DNS is resolved for every connection and the checked IP is pinned; HTTPS uses the original hostname for SNI and certificate verification. HTTPS redirects cannot downgrade to HTTP. Authorization headers are sent only to the original endpoint's origin.

The streaming-sources service is included in docker-compose.streaming.yml. It runs one job at a time; the API admits four source jobs globally by default and 100 registered definitions per environment. Scale workers within that global budget if needed. Probes occupy source capacity too. The image uses the existing native FFmpeg network guard, read-only filesystem, dropped capabilities, no-new-privileges, one CPU, 1 GiB RAM and 128 processes. FFprobe and FFmpeg receive only PATH and guard settings. They can connect only to two job-local loopback proxies; they cannot fetch upstream URLs or follow arbitrary redirects themselves. The Node transport handles remote HTTP requests and a separate trusted proxy reaches the private ingest gateway. Do not replace the supplied dynamically linked Linux binaries with unguarded binaries.

Use a deployment firewall/network policy to allow this worker DNS, the private API and ingest gateway, and approved public source addresses on 80/443. Block metadata and unrelated private networks at the network layer as well. Keep the API, storage and gateway management ports private. Allowlist all CDN segment hosts explicitly, including redirect targets. TLS errors must be fixed at the upstream; certificate verification cannot be disabled.

## Limits and lifecycle
Pull requests have a 10-second deadline, at most three redirects, 16 KiB headers, 256 KiB/2000-line manifests, 16 MiB objects, four concurrent fetches, 100 fetches and 8 MiB per second, and 4096 discovered resources per attempt. Exceeding a limit fails the attempt. Sources default to 2 GB fetched bytes, four hours and three reconnect retries; administrators can lower these per source. Duration is capped by the attached stream and cannot exceed 24 hours. A probe has a 60-second overall window and a 20-second FFprobe deadline. The same media profile and transport restrictions apply during probe and actual ingest.

Source states include created, probing, ready, connecting, live, recovering, stopped and failed. Only observed canonical live media emits source_connected. Failures restart within the configured retry budget with a five-second delay. Timestamp discontinuities are handled by the HLS reader and the canonical normalization worker. New attempts use new fenced credentials. Heartbeats renew 15-second ownership; workers stop locally if control confirmation is absent for 11 seconds. Expired leases revoke ingest credentials and stop the canonical publisher before another attempt can be admitted. A transient recovery can therefore create a new canonical session and playback generation; the existing player follows it.

Deleting an active source stops its ingest and dependent stream broadcasts, clears its encrypted authentication material, and preserves session history and usage. Parent stream/environment/project/organization retirement also cancels sources. A registered source's stream and protocol are immutable. Stop and wait for a terminal session before editing it. Stream protocol changes require deleting its registered sources first. Stopping a source does not delete an already finalized recording.

## Credentials, events and usage
Upstream URL paths, query tokens and Authorization are encrypted with STREAMING_DESTINATION_ENCRYPTION_KEY and a source/version-specific encryption context. Ordinary reads return only protocol/host and a configured flag. Patch the endpoint or authorization with the current source version to rotate them. Send an empty authorization value to remove a header. Rotate the deployment encryption key only with a coordinated re-encryption procedure; changing it alone makes existing ciphertext unreadable.

Subscribe to restream.probing, restream.source_connected, restream.source_lost, restream.recovering, restream.stopped and restream.failed. Delivery uses the existing signed webhook outbox. Health history retains the latest 50 transitions; events contain identifiers and safe failure reasons, never raw upstream diagnostics or URLs.

Source detail usage counts observed upstream fetch bytes, including probes, retries, manifests and initialization data, separately from broadcast output bytes. Processing seconds count the probe and pull media processes' observed elapsed time, not CPU billing or canonical transcode time. Lost observations after a worker crash are not estimated. Push traffic is counted by the normal stream usage system; registry monitoring adds no duplicate traffic charge. Source history persists across deletion. Prometheus exposes aggregate active sessions, expired leases, observed fetched bytes and processing seconds, plus worker counters.

## Troubleshooting
SOURCE_ADDRESS_REJECTED means a host/port, DNS answer or local-loop rule was rejected. Check every CDN host and redirect. SOURCE_BUSY requires stopping the active operation before editing or probing again. SOURCE_CAPACITY means the global source-job limit is full. PUBLISHER_CONFLICT means another publisher still owns the attached stream; wait for its teardown. SOURCE_CONNECTION_TIMEOUT means a push publisher did not connect or reconnect within its window. SOURCE_PROBE_TIMEOUT means a queued/active probe exceeded its overall deadline. SOURCE_PROFILE_UNSUPPORTED rejects an unsupported codec or playlist profile. SOURCE_BYTE_LIMIT means the source exhausted its byte budget. SOURCE_CANONICAL_FAILED means the normal source worker could not produce a program. SOURCE_FETCH_FAILED and SOURCE_PROCESSING_FAILED are deliberately generic: check the upstream's H.264/AAC profile, supported playlist features, TLS certificate and operator network rules. A probe can succeed while a subsequent live fetch fails because the source changed. Repeated failures exhaust the reconnect budget; repair the input and start a new session. Never expose raw FFmpeg diagnostics to viewers.
