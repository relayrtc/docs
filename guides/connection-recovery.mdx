## Room state

```tsx
import { MediaLoader, RelayProvider, RelayRoom, useRoom } from '@relayrtc/react'
```

```tsx
const { connectionState, error } = useRoom()

if (connectionState === 'reconnecting') return <MediaLoader label="Reconnecting to the call" />
if (connectionState === 'failed') return <p role="alert">{error?.message}</p>
```

The default reconnect policy allows 6 attempts within 25 seconds. It restores the existing session and repairs media transport when possible.

## Playback loading

`useMediaTrack` reports loading while a remote track is starting or its room is reconnecting. Keep the media element mounted so the hook can attach it after recovery.

If recovery fails, offer a deliberate rejoin flow. A room that ended or a participant that was removed cannot be restored by retrying indefinitely.

## TURN renewal

Provide a server-backed callback when issuing TURN credentials:

```tsx
<RelayProvider
  signalingUrl={signalingUrl}
  refreshTurnCredentials={async ({ roomId, sessionId, signal }) => {
    const response = await fetch('/api/turn', {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      body: JSON.stringify({ roomId, sessionId }),
      signal,
    })
    if (!response.ok) throw new Error('TURN renewal failed')
    return response.json()
  }}
>
  <RelayRoom token={token}><YourCall /></RelayRoom>
</RelayProvider>
```

`YourCall` is your call component. Authenticate `/api/turn` on your server and check that the caller owns the requested session. Your server uses [turn.createCredentials](/reference/sdk/server/node/turn/createCredentials).

## Participant token expiry

The creation endpoint issues a new participant identity. For an ongoing call, use [`tokens.renew`](/reference/sdk/server/node/tokens/renew) on your backend and provide `refreshToken` to the browser SDK or React `RelayProvider`. Matching local API/SDK builds are required; older deployments do not expose the renewal endpoint.

```tsx
import { RoomError } from '@relayrtc/react'

<RelayProvider
  signalingUrl={signalingUrl}
  refreshToken={async ({ roomId, participantId, sessionId, signal }) => {
    const response = await fetch('/api/renew-participant', {
      method: 'POST', signal,
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ roomId, participantId, sessionId }),
    })
    if ([401, 403, 404].includes(response.status)) return null
    if (!response.ok) throw new RoomError('TOKEN_REFRESH_FAILED', 'Renewal unavailable', response.status >= 500 || [408, 429].includes(response.status))
    return (await response.json()).token
  }}
>
  <RelayRoom token={token}><YourCall /></RelayRoom>
</RelayProvider>
```

Your `/api/renew-participant` endpoint authenticates the caller, looks up their current participant token in server-side session storage, verifies room access and calls `relay.tokens.renew(roomId, { participantToken: storedToken, sessionId, ttlSeconds: 600 })`. Save the replacement token for subsequent renewals. Use the same configured lifetime as initial issuance; do not silently shorten a one-hour token to the ten-minute default.

The callback runs before expiry. The SDK applies the new credential through `session.refresh`, preserves the room/participant/session and existing media, and uses the replacement token for later reconnects. Each token remains limited to 60–3600 seconds; repeated authorized renewal supports longer meetings.

Returning `null` denies renewal. Changed identity/permissions and explicit authorization errors terminate the call. Retryable `RoomError` failures and ordinary callback exceptions receive bounded-backoff retries while the current token remains valid; expiry still ends the session. Mark permanent application failures non-retryable. Without a callback, expiry requires a deliberate rejoin. `autoSubscribe` only controls receiving media and does not configure renewal.

Streaming guest grants use their existing guest-specific renewal flow.

## Startup delays

Capture, publication, subscription, ICE negotiation and the first decodable frame all take time. Subscription success does not mean the video has started playing.

Use playback state to show waiting and measure connection stages when investigating a slow start. A loader does not change transport setup time.
