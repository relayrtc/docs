Streaming is included in the standard [setup wizard](/self-hosting). PostgreSQL, rooms, mediasoup, coturn, streaming workers, the ingest gateway and private storage share one generated Compose project.

## Services and credentials

The complete stack has 16 services. Source, output, recording and room-export workers use the same release's streaming image with role-specific commands. The wizard generates independent credentials and saves them in the installation folder.

From that folder:

```sh
docker compose ps -a
docker compose logs --tail=100 streaming-worker streaming-gateway
```

`migrate` and `streaming-storage-init` exit with code 0 after successful initialization. Healthy containers alone do not establish working ingest or playback.

## Default local addresses

| Setting | Default |
| --- | --- |
| `STREAMING_PUBLIC_ORIGIN` | `http://localhost:8080` |
| `STREAMING_PUBLIC_RTMP_ORIGIN` | `rtmp://127.0.0.1:1935` |
| `STREAMING_GUEST_SIGNALING_URL` | `ws://localhost:8081/v1/connect` |
| `STREAMING_INGEST_BIND` | `127.0.0.1` |
| `STREAMING_WEBRTC_HOSTS` | `127.0.0.1` |

The wizard derives public streaming addresses from your API, signaling and media settings. Review RTMP/WHIP routing separately for remote publishers. `STREAMING_ALLOWED_ORIGINS` must include each browser application's exact origin. External HLS pulls require an explicit `STREAMING_SOURCE_ALLOWED_HOSTS` allowlist.

Use [settings management](/guides/self-hosting-operations#change-settings) for later changes. Update saved public origins explicitly when changing host ports.

## Publish and play

1. Connect a [room or encoder](/guides/streaming-ingest).
2. Create and start a [broadcast](/guides/broadcasts).
3. Wait for `readiness.viewerReady`.
4. Authorize a viewer using [private playback](/guides/streaming-playback).

Remote encoders and viewers also need [public streaming access](/guides/streaming-operations#configure-public-access) and the base [media/TURN ports](/guides/self-hosting-operations#public-hosting-and-ports).
