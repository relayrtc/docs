Streaming is included in the standard [RelayRTC installation](/self-hosting). The normal `pnpm docker:up` source command starts calls, streaming workers, the ingest gateway and private storage together. Release installations start the same services with prebuilt images.

Use this page to check addresses and media flow after installation. There is no separate streaming installation or enablement step.

## Download streaming configuration

The [v0.1.2 release ZIP](https://github.com/relayrtc/relayrtc/archive/refs/tags/v0.1.2.zip) already includes the complete configuration. The installation guide uses `docker-compose.yml`, `docker-compose.streaming.yml` and both release image overrides.

Keep these files together with `.env`, `.streaming` and the `infrastructure` directory.

## Prepare credentials and monitoring

The [standard settings preparation](/self-hosting#4-create-your-settings-file) generates all call and streaming credentials and prepares `.streaming` automatically. `pnpm env:configure` and `pnpm docker:up` do the same from a source checkout.

Preparation keeps configured provider credentials, signing/encryption keys and public addresses. An older `RELAYRTC_STREAMING_ENABLED=false` value is updated to the standard enabled setting. Keep `.env` and `.streaming` private.

## Review the local addresses

For testing on this computer, generated settings use these addresses:

| Setting | Default |
| --- | --- |
| `STREAMING_PUBLIC_ORIGIN` | `http://localhost:8080` |
| `STREAMING_PUBLIC_RTMP_ORIGIN` | `rtmp://localhost:1935` |
| `STREAMING_GUEST_SIGNALING_URL` | `ws://localhost:8081/v1/connect` |
| `STREAMING_INGEST_BIND` | `127.0.0.1`, for an encoder on this computer |
| `STREAMING_WEBRTC_HOSTS` | `127.0.0.1` |

The API and signaling addresses are derived from the base ports when first prepared. Existing values are preserved, so review them after changing a port or moving to a VPS.

`STREAMING_ALLOWED_ORIGINS` must include your viewing application's exact origin, such as `http://localhost:3005`. Internal worker, gateway and storage addresses remain private Docker addresses. External HLS pulling requires an explicit source-host allowlist.

For encoders or viewers on another device, configure [public streaming access](/guides/streaming-operations#configure-public-access).

## Check the services

For a source checkout:

```sh
pnpm docker:status
```

For a release installation, use the same configuration as startup:

```sh
docker compose --env-file .env -f docker-compose.yml -f docker-compose.streaming.yml -f docker-compose.release.yml -f docker-compose.streaming.release.yml ps -a
```

The standard stack contains 16 services. Long-running services should be running, with healthy results where health checks are configured. `migrate` and `streaming-storage-init` are one-time setup services; `Exited (0)` is expected.

## Publish and play a stream

1. Connect a [room or encoder](/guides/streaming-ingest).
2. Create and start a [broadcast](/guides/broadcasts).
3. Wait for playback metadata to report `readiness.viewerReady`.
4. Authorize a viewer and render [private playback](/guides/streaming-playback).

Test recordings, clips, DVR and other capabilities separately when using them. A connected encoder or healthy container does not establish playable media.

## Stop or inspect the stack

Use `pnpm docker:logs` and `pnpm docker:down` in a source checkout. For release images, use all four Compose files as described in [installation](/self-hosting#stop-and-troubleshoot).

End active calls, broadcasts and recordings before stopping services. For a deployment serving users, follow the [draining procedure](/guides/streaming-operations#upgrades-and-draining).
