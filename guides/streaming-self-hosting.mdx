Streaming is part of the standard [RelayRTC installation](/self-hosting). The setup image starts its workers, ingest gateway and private storage together with rooms. There is no additional streaming download, installation or enablement command.

## Services and credentials

The complete stack has 16 services. Streaming uses source, output, recording and room-export workers, a MediaMTX ingest gateway and private object storage. The installer generates their credentials and keeps the original values across restarts.

Inspect the stack with the setup image's `status` or `logs` command from [installation](/self-hosting#start-inspect-or-stop). Successful `migrate` and `streaming-storage-init` containers exit with code 0. A healthy container does not by itself establish working ingest or playback.

## Default local addresses

| Setting | Default |
| --- | --- |
| `STREAMING_PUBLIC_ORIGIN` | `http://localhost:8080` |
| `STREAMING_PUBLIC_RTMP_ORIGIN` | `rtmp://localhost:1935` |
| `STREAMING_GUEST_SIGNALING_URL` | `ws://localhost:8081/v1/connect` |
| `STREAMING_INGEST_BIND` | `127.0.0.1` |
| `STREAMING_WEBRTC_HOSTS` | `127.0.0.1` |

`STREAMING_ALLOWED_ORIGINS` must contain the viewing application's exact origin. External HLS pulls require `STREAMING_SOURCE_ALLOWED_HOSTS`; an empty value disables those pulls. Internal API, gateway and storage endpoints remain private Docker addresses.

Use [settings management](/guides/self-hosting-operations#change-settings) to change these values. Existing public addresses are preserved; changing a host port does not automatically rewrite them.

## Publish and play

1. Connect a [room or encoder](/guides/streaming-ingest).
2. Create and start a [broadcast](/guides/broadcasts).
3. Wait for `readiness.viewerReady`.
4. Authorize a viewer using [private playback](/guides/streaming-playback).

For remote encoders and viewers, use [public streaming access](/guides/streaming-operations#configure-public-access) together with [public hosting](/guides/self-hosting-operations#public-hosting-and-ports).

Installer-managed gateway configuration, certificates and monitoring files live in isolated subdirectories of the persistent configuration volume. No source-checkout bind mounts are needed. See [configuration storage](/guides/self-hosting-operations#configuration-and-data) before supplying custom certificates.

For source development, `pnpm docker:up` still starts the same complete stack using the repository's Compose definitions. The streaming-named script aliases remain compatibility aliases, not separate deployments.
