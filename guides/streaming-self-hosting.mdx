## Availability
Unreleased Phase 0 deployment files live in core `docker-compose.streaming.yml` and `infrastructure/streaming/README.md`. Use matching local SDK builds until the additions are released. No services start as a result of installing an SDK.

## Setup
Configure the [base stack](/self-hosting), then fill streaming variables in core `.env.example`. Generate three distinct base64url secrets for signing, worker bootstrap and gateway callback authentication. Configure private storage administrator credentials and a separate restricted API storage user. Run from the core repository:

```sh
node --env-file=.env scripts/prepare-streaming.mjs
docker compose --env-file .env -f docker-compose.yml -f docker-compose.streaming.yml config --quiet
```

The preparation command only writes ignored local monitoring secrets. When the operator is ready to start the deployment, use the same Compose files with `up --build -d`. This starts the base migration service and applies prepared migrations to the configured database. Back up metadata, bucket and signing/encryption secrets first.

The override adds MediaMTX 1.21.2, a worker image with FFmpeg 7.1-compatible codecs and private S3-compatible storage built from pinned MinIO OSS source releases. Storage initialization denies public access and grants the API object-only access under `streaming/*`. Review included upstream licenses before distributing images. An existing private S3 service can replace local storage through an operator override.

## Public and private ports
Expose the API playback/WHIP routes through trusted HTTPS. Block `/internal/` at the public proxy. Keep gateway control 9997, HLS 8888, WHIP 8889, RTSP 8554, metrics 9998, worker health 8090, S3 9000 and RTP export UDP 20000..20023 private. Forward SDP/trickle content types and allow bounded LL-HLS reload timeouts; avoid query/token access logs and shared caching.

Production RTMPS needs a trusted certificate/key, a returned `rtmps://` public origin and strict/optional encryption. Public WHIP ICE needs reachable advertised addresses and UDP 8189 or configured ICE/TURN. Local defaults bind/advertise loopback. TURN for RTC and HTTP HLS are separate transport concerns.

## Capacity and monitoring
One isolated worker process runs one source at a time. This local recipe uses one fixed private RTP receiver IP; do not scale it with duplicate IPs. Admission limits and available workers are different controls. Watch queue age, live/reconnecting sessions, expired leases, worker busy/memory, control age, encoder failures, storage usage, pending uploads and cleanup. Prometheus and the Streaming foundation Grafana dashboard integrate with existing monitoring. Source usage is measured from server observations and carries observed/partial coverage; it does not bill HLS audiences.

## Recovery
Inspect safe source error codes for unsupported codecs, absent tracks, expired credentials and ICE failures. Fix storage before retrying cleanup; keep API maintenance active until durable stop/delete operations complete. Reissue authorized playback grants and reconcile generation after encoder restart. The player may rebuffer.

Stop active sources and wait for operations before shutting down workers/gateway. Keep API and storage running through cleanup. Disabling the feature flag also disables maintenance; drain before disabling. Restore metadata/bucket/secrets with workers and gateway stopped, allow stale leases to reconcile and deliberately re-enable publishing. Never restore a live worker snapshot.

The core operator README contains exact variables, commands, license notes and rollback details. Compilation/configuration checks do not establish live protocol interoperability. [Ingest setup](/guides/streaming-ingest) and [private playback](/guides/streaming-playback) describe supported behavior.

## Broadcast orchestration (unreleased Phase 1)

The same optional Compose override also supplies the streaming-outputs service. It runs independently of the source encoder and defaults to four concurrent HLS attachment jobs, with private health/metrics on port 8091. Migration 0033 adds run snapshots, jobs, attempts, reservations and usage. Apply it through the existing migrator only when deliberately deploying matching images.

Configure the STREAMING_MAX_BROADCASTS, STREAMING_MAX_BROADCASTS_PER_ENVIRONMENT, STREAMING_MAX_OUTPUT_JOBS, STREAMING_MAX_OUTPUT_JOBS_PER_WORKER and STREAMING_OUTPUT_CONCURRENCY limits. To drain broadcasts while keeping source cleanup active, set STREAMING_BROADCASTS_ENABLED=false on the API and restart it; leave RELAYRTC_STREAMING_ENABLED=true. The Broadcast orchestration dashboard exposes queue/lease/output health. See [broadcast runs](/guides/broadcasts) for commands, snapshot behavior, recovery and exact operational limits.

## External destinations
Phase 2 adds a separate STREAMING_DESTINATION_ENCRYPTION_KEY and a guarded Linux output worker. The local pnpm docker:up:streaming command generates a missing key. Back up this key with the database and upgrade all components together. See [multistreaming deployment and network requirements](/guides/multistreaming). ## Recording worker
Matching Phase 3 builds add the isolated `streaming-recordings` service and migration 0035. Apply after 0033/0034 with the migration service before starting the upgraded API. The worker uses private API access, the existing FFmpeg guard and bounded temporary storage. Configure STREAMING_MAX_RECORDINGS (default 4), STREAMING_MAX_RECORDINGS_PER_ENVIRONMENT (2), and STREAMING_MAX_RECORDING_BYTES (536870912). Existing signing/S3 credentials are reused. See [Recording and VOD](/guides/recording-and-vod) for retention, consent, region and format limits.

## Scheduled events
Migration 0036 and matching API/console/SDK builds add the database-backed scheduler. It runs inside each streaming-enabled API process, with fenced PostgreSQL claims and no browser/cron dependency. Configure STREAMING_MAX_SCHEDULES (1000) and STREAMING_MAX_SCHEDULES_PER_ENVIRONMENT (100). Optional signed-webhook reminders require STREAMING_SCHEDULE_NOTIFICATIONS_ENABLED=true and an enabled schedule.reminder subscription. No email provider is assumed. See [Scheduled broadcasts](/guides/scheduled-broadcasts) for source readiness, access windows and downtime policy.

## External source workers
Migration 0037 adds the source registry and durable probe/pull sessions. Upgrade API, source, composition and output workers together; use the matching local SDK/console builds. The streaming overlay includes streaming-sources. Configure exact STREAMING_SOURCE_ALLOWED_HOSTS before pulling media. Empty disables pulls. See [restreaming deployment](/guides/restreaming) for guarded egress, TLS, limits, credential rotation and observed usage. Before rollback, stop source jobs and wait for leases to drain; preserve the registry/session/usage tables and do not drop historical data.

## Playback origin and private HLS proxy
STREAMING_PUBLIC_ORIGIN must match the browser-facing API address, including its published port. For example, API_PORT=8082 on a local machine requires STREAMING_PUBLIC_ORIGIN=http://localhost:8082. It differs from the internal Docker address http://api:8080.

MediaMTX 1.21 HLS uses browser-session redirects by default. The streaming overlay configures MTX_HLSCDNSECRET from the existing private STREAMING_GATEWAY_KEY, and only the API uses that credential on upstream HLS requests. This protected reverse-proxy mode emits relative media names without gateway browser sessions. Keep gateway HLS port 8888 private; never send the gateway credential to viewers. Public playback still verifies the scoped viewer grant, current ownership, revocation epoch and session state on every request.

## Stream workspace console

Rebuild matching API and console images for the stream workspace navigation. Apply additive migration 0042 through the normal migration service; its indexes support recent-history and active-run selection for each stream. The console keeps one selected environment and broadcast across sections, and old project-wide streaming pages redirect to Streams. No additional service or environment setting is needed.
